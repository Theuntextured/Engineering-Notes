# Introduction to Trusted Computing

## Trust vs. Security
* **Security:** A system enforces a defined security policy under a specific threat model.
* **Trust:** A system behaves in a predictable or expected way; however, predictable behavior (like a thief stealing) is not necessarily secure behavior.
* **Confidential Computing:** Protects data *in use* during computation. Approaches include Trusted Execution Environments (TEEs) for hardware isolation, Fully Homomorphic Encryption (FHE) for computing on encrypted data, and Secure Multi-Party Computation (SMPC) for split joint computation.

## Roots of Trust (RoT) & Certification
* **Roots of Trust:** Foundational components trusted by design because their misbehavior cannot be detected at runtime. These include RTM (Measurement), RTS (Storage), RTR (Reporting), RTD (Detection), and RTU (Update).
* **Hardware Security Modules (HSMs) & Smart Cards (EMV):** Act as physical RoTs, isolating keys and cryptographic operations from the host OS.
* **Common Criteria:** International certification framework evaluating products from EAL 1 (basic) to EAL 7 (formally verified).
* **FIPS 140-3:** US standard for certifying cryptographic modules from Level 1 (basic) to Level 4 (tamper-resistant).

## The Trusted Platform Module (TPM 2.0)
* **Definition:** A standardized hardware trust anchor that provides RTS (storage) and RTR (reporting). It does *not* provide RTM; the Core Root of Trust for Measurement (CRTM) lives outside the TPM in firmware.
* **Platform Configuration Registers (PCRs):** Shielded memory slots in the TPM. They cannot be overwritten; they are updated via the `Extend` operation: `PCRnew = Hash(PCRold || measurement)`. They provide a tamper-evident history of the boot sequence.
* **Measured vs. Secure Boot:**
  * **Measured Boot:** Records what was loaded by extending hashes into PCRs and Event Logs (detects later).
  * **Secure Boot:** Verifies signatures before executing code and halts the boot if validation fails (enforces now).

## TPM Keys & Operations
* **Endorsement Key (EK):** The long-term, manufacturer-certified TPM identity key. It is privacy-sensitive and never used for routine signing.
* **Attestation Key (AK):** An operational alias key generated by the TPM to sign quotes. It is certified by a Privacy CA to prove it resides in a genuine TPM alongside the EK.
* **Sealing:** Binding a secret to a specific platform state, meaning it can only be decrypted if the PCRs match exact expected values.
* **TSS 2.0:** The software stack (FAPI, ESAPI, SAPI) that bridges user applications and the TPM.

# Remote Attestation and IMA

## Remote Attestation Fundamentals
* **Definition:** A process where a platform (Attester) provides cryptographic evidence of its state to a remote entity (Verifier) to establish trust.
* **Freshness:** The Verifier always sends a random `nonce` to be included in the TPM quote; this prevents attackers from replaying old, "healthy" evidence.
* **IETF RATS Architecture:** Standardizes the roles (Attester, Verifier, Relying Party) and the information flow (Evidence, Endorsements, Reference Values, Appraisal Policy).

## The Verification Pipeline
* **TPM Quote:** A signature generated by the AK over selected PCR values and the Verifier's nonce.
* **Event Log Validation:** Because PCRs are only cryptographic aggregates, the Verifier must retrieve the Event Log. The Verifier replays the hash extensions from the log to see if the final result matches the TPM Quote. If it matches, the log is authentic.
* **Appraisal:** Once the log is validated, the Verifier compares individual measurement events against "Golden" Reference Values to determine if the software is approved.

## Integrity Measurement Architecture (IMA)
* **Purpose:** Trusted Boot only checks how the system started; IMA (a Linux kernel module) extends the chain of trust into runtime.
* **Mechanism:** Measures executables, shared libraries, and scripts *before* they execute. It logs the events in the IMA Measurement Log and extends their digests into PCR 10.
* **Limitation:** IMA measures structured data (files, policies) but cannot measure dynamic data (user input, network traffic).

## Keylime
* **Definition:** An open-source framework for scalable TPM-based remote attestation and runtime IMA monitoring.
* **Secure Payload Provisioning:** Keylime uses a split-key mechanism (U and V). The Tenant encrypts a payload and sends the encrypted file to the Agent, but the Verifier only releases the final decryption key piece (V) to the Agent *after* the first successful remote attestation.
* **Continuous Monitoring:** Keylime constantly challenges the node; if the IMA log or PCRs deviate from the policy, it triggers a revocation event to isolate the compromised machine.
